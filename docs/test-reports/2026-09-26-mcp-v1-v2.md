# MCP V1 + V2 — vérification du 26 septembre 2026

## Résultat

Implémentation locale du connecteur, de ses 12 outils, du consentement OAuth, de la gestion des connexions et de la validation des SMS. La migration est livrée dans le dépôt ; cette intervention ne l’a pas appliquée au projet hébergé et n’a pas activé OAuth ni déployé l’API.

Les tests HTTP utilisent le vrai SDK MCP 2.1.0 et les transports 2025-11-25 / 2026-07-28. Supabase Auth, PostgREST et Twilio y sont simulés. Ils couvrent les refus d’authentification, audience, rôle, émetteur, expiration, origines, contrôle des routes `/v1`, outils, erreurs, quotas et reprises SMS. Les subscriptions longues inutilisées sont désactivées.

Les tests PostgreSQL appliquent les vraies migrations et vérifient les politiques RLS, les droits de colonnes et de fonctions, l’isolation des organisations/lignes, les modifications de contacts avec version et idempotence, les brouillons, la validation humaine, les refus, l’expiration et la reprise après expiration de la clé HTTP. Ils testent aussi le hook OAuth avec des claims reconstruits au renouvellement et empêchent une ancienne session d’adopter une nouvelle autorisation.

## Recette navigateur

Recette Playwright des composants React réels avec données fictives et API simulée :

- Connexions et permissions affichées ; révocation exécutée.
- Consentement : organisation, permissions et lignes ; autorisation impossible sans ligne quand une permission en demande une ; redirection après autorisation.
- Validation SMS : ligne, destinataire, texte, expiration et segments visibles ; un clic produit une validation et un seul envoi simulé ; le résultat distingue envoi et livraison.
- Refus SMS sur mobile : aucun envoi ni validation ; les boutons d’envoi disparaissent.
- Largeur mobile 390 px : aucun débordement horizontal ; dialogue et boutons utilisables.
